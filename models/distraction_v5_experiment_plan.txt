1. CONFIRMED WEAKNESSES IN V4
===============================================================================

1.1 Person Imbalance in Training Data
- Training set: 4,578 images
- "me": 2,085 images (45.5% of training data)
- friend 1: 430 images (9.4%)
- friend 2: 432 images (9.4%)
- friend 3: 834 images (18.2%)
- friend 4: 797 images (17.4%)
- "me" is 4.8x more represented than any other person
- This leads to person-specific bias and poor generalization

1.2 Catastrophic Performance on Specific People
- Friend 3 validation: 32.63% accuracy (V4), 27.37% (V3)
- Friend 4 validation: 28.57% accuracy (V4), 20.92% (V3)
- These two represent 36% of validation set (386 of 1,072 images)
- Both models fail catastrophically on these people

1.3 Session Distribution Mismatch
- session2: 164 validation images (friend 1, friend 2) - V4: 69.51%
- session3_raw: 908 validation images (friend 3, friend 4, me) - V4: 52.42%
- session3_raw is 34% brighter, 19% lower contrast than session2
- Neither model generalizes to session3_raw-only data (Friend 5)

1.4 Safe Driving Over-Prediction
- V4 on Friend 5: 98.82% recall, 13.46% precision
- V3 on Friend 5: 100% recall, 11.46% precision
- Both models default to safe driving for unfamiliar samples
- Suggests model lacks confidence for other classes

1.5 Complete Failure on Specific Classes
- Operating radio (c5): 0% recall on Friend 5 (both models)
- Reaching behind (c7): 0% recall on Friend 5 (both models)
- Hair/makeup (c8): 2-3% recall on Friend 5 (both models)
- These classes are systematically difficult

1.6 Limited Cross-Person Generalization
- V4 on Friend 5: 27.91% accuracy
- V3 on Friend 5: 24.51% accuracy
- Both models fail catastrophically on unseen person
- Session distribution is primary cause, but person imbalance exacerbates it

2. PROPOSED CHANGES FOR V5
===============================================================================

2.1 Person-Balanced Sampling
- Implement weighted sampling to reduce "me" dominance
- Target sampling distribution: equal weight per person
- Calculate sample weights inversely proportional to person frequency
- Apply weights during training only (not validation)
- Preserve all original images and temporal groups
- No file duplication - use tf.data weighted sampling

2.2 Enhanced Augmentation for Session Variation
- Add brightness augmentation: [-0.3, +0.3] to simulate session differences
- Add contrast augmentation: [-0.3, +0.3] to simulate session differences
- Add hue rotation: [-0.1, +0.1] for color variation
- Keep existing augmentations: rotation (0.06), translation (0.08), zoom (0.10)
- NO horizontal flips (preserves left/right distinction)
- Apply only to training data

2.3 Conservative Training Strategy
- Use V4 checkpoint as initialization (V4 performed better than V3)
- Reduce Phase 1 learning rate to 5e-5 (from 1e-4)
- Reduce Phase 2 learning rate to 5e-6 (from 1e-5)
- Increase early stopping patience to 10 (from 8)
- Add L2 regularization (1e-4) to classification head
- Add dropout (0.5) before final layer

2.4 Improved Checkpoint Selection
- Select based on validation macro F1 (not just accuracy)
- Use early stopping on validation loss with patience
- Monitor overfitting by tracking train/val gap
- Save best Phase 1 and Phase 2 checkpoints separately

4. SAMPLING STRATEGY
===============================================================================

4.1 Weight Calculation
Current training distribution:
- "me": 2,085 images (45.5%)
- friend 1: 430 images (9.4%)
- friend 2: 432 images (9.4%)
- friend 3: 834 images (18.2%)
- friend 4: 797 images (17.4%)

Target: Equal weight per person (20% each)
- Weight = (target_fraction) / (actual_fraction)
- "me": 0.20 / 0.455 = 0.44
- friend 1: 0.20 / 0.094 = 2.13
- friend 2: 0.20 / 0.094 = 2.13
- friend 3: 0.20 / 0.182 = 1.10
- friend 4: 0.20 / 0.174 = 1.15

4.2 Implementation
- Create person-to-weight mapping dictionary
- Add "person" column to training dataset (from manifest)
- Use tf.data.sample_from_datasets with weights
- Or use custom tf.data dataset with weighted shuffling
- Apply weights during training only
- Validation remains uniform (no weighting)

4.3 Preserving Temporal Groups
- Temporal groups are defined within each person's recording
- Weighted sampling operates at the image level, not group level
- Within each person, temporal groups remain intact
- Sampling affects how often each person's batches appear, not group structure

4.4 No File Duplication
- No image files are copied or modified
- Weighted sampling is achieved through tf.data operations
- Original dataset remains unchanged

5. AUGMENTATION STRATEGY
===============================================================================

5.1 Existing V4 Augmentations (Preserved)
- RandomRotation: 0.06 (approx 3.4 degrees)
- RandomTranslation: 0.08 (8% of image width/height)
- RandomZoom: 0.10 (10% zoom in/out)
- RandomBrightness: 0.15 (15% brightness variation)
- RandomContrast: 0.15 (15% contrast variation)

5.5 Proposed New Augmentations
- RandomBrightness: Increased to 0.30 (30% variation)
- RandomContrast: Increased to 0.30 (30% variation)
- RandomHue: 0.10 (10% hue rotation)
- Reason: Simulate session3_raw brightness/contrast differences

5.3 Rationale
- session3_raw is 34% brighter than session2
- session3_raw has 19% lower contrast than session2
- Increased brightness/contrast augmentation simulates these variations
- Hue rotation adds color variation for robustness
- NO horizontal flips (preserves left/right distinction)

5.4 Application
- Augmentation only applied to training data
- Validation data has NO augmentation
- Test data has NO augmentation
- Augmentation applied via tf.keras.Sequential layer

8. RISKS AND LIMITATIONS
===============================================================================

8.1 Dataset Limitations
- Only 6 people total - insufficient for robust generalization
- Friend 5 is the only held-out person - limited evaluation
- Session distribution mismatch is fundamental - may not be fully solvable
- Class imbalance in some classes (especially on Friend 5)

8.2 Sampling Risks
- Person-balanced sampling may reduce overall accuracy on "me"
- May not improve Friend 5 performance if session differences dominate
- Weighted sampling may require more epochs to converge

8.3 Augmentation Risks
- Excessive augmentation may degrade model performance
- Brightness/contrast augmentation may not fully capture session differences
- Hue rotation may introduce unrealistic color variations

8.4 Generalization Risks
- May not achieve >50% accuracy on Friend 5
- May still fail on Operating radio and Reaching behind
- May still over-predict safe driving on unseen data
- Session distribution mismatch may be fundamental barrier

8.5 CPU-Only Training
- Slower training than GPU
- Limits ability to run many experiments
- May restrict hyperparameter tuning
