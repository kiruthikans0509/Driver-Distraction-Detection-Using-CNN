3. TEMPORAL GROUP SAFEGUARDS
===============================================================================

3.1 Distinction: Train/Validation Split vs Epoch Sampling

TRAIN/VALIDATION SPLIT (Fixed, Uses Manifests):
- Temporal groups are preserved during train/validation split
- V4 manifests already have temporal-group separation (verified in Stage A)
- Train.csv contains specific temporal groups that do not overlap with validation.csv
- NO validation image can enter the training pipeline because:
  * Training and validation are loaded from separate manifest files
  * Validation dataset is created exclusively from validation.csv
  * Training dataset is created exclusively from train.csv
  * There is no cross-manifest loading or mixing
- This is FIXED and does not change during sampling

EPOCH SAMPLING (During Training):
- Weighted sampling occurs within the training split only
- Affects frequency of each training sample appearing per epoch
- Does NOT affect which samples are in training vs validation
- Does NOT move samples between train and validation
- Does NOT introduce validation images into training pipeline

3.2 Verification of No Validation Contamination
- Training pipeline: Load train.csv → create training dataset
- Validation pipeline: Load validation.csv → create validation dataset
- These are separate tf.data.Dataset objects
- No cross-pollination between the two datasets
- Weighted sampling only applies to training dataset
- Validation dataset remains completely separate

3.3 Risk: Repeated Selection from Recording Bursts
PROBLEM: Image-level weighted sampling may repeatedly select near-identical frames from the same recording burst (same temporal group)

CURRENT TEMPORAL GROUP STRUCTURE:
- Temporal groups are defined with 10-second gap threshold
- Each group contains consecutive frames from the same recording
- Groups are kept intact during train/validation split
- Within each group, frames are temporally close (sub-second intervals)

WEIGHTED SAMPLING EFFECT:
- Underrepresented persons (friend 1, friend 2) have higher weights (~2.13)
- Their images will be selected more frequently per epoch
- If a person has many images in one temporal group, that group will be oversampled
- This could lead to repeatedly seeing nearly identical frames from the same burst

MITIGATION STRATEGY (Group-Aware Sampling):
- RECOMMENDATION: Implement group-aware sampling instead of image-level sampling
- Group temporal groups by (person, temporal_group, class_id) identifier
- Calculate weights at the GROUP level, not image level
- Sample entire groups (or randomly select frames within groups) rather than individual images
- This preserves temporal context while still balancing person representation

REVISED SAMPLING ALGORITHM:
1. From training manifest, extract (person, temporal_group, class_id) for each image
2. Group images by (person, temporal_group, class_id) → unique "person-group-class" combinations
3. Count n(p,g,c) = number of images in each person-group-class combination
4. Calculate target = N_total / (n_persons * n_groups * n_classes)
5. Calculate weight(p,g,c) = target / n(p,g,c)
6. Create separate dataset for each person-group-class combination
7. Use tf.data.sample_from_datasets with these 50+ datasets and corresponding weights
8. This ensures balanced sampling while avoiding repeated identical frames from same burst

EXPECTED REPEATED SELECTIONS:
- Without group-aware sampling: Underrepresented persons' frames from same burst would repeat 2-3x per epoch
- With group-aware sampling: Each group is sampled as a unit, reducing temporal redundancy
- Near-identical frames from same burst will still appear multiple times, but less frequently

ALTERNATIVE (If Group-Aware Sampling Too Complex):
- Keep image-level weighted sampling but add "unique identifier" tracking
- Use tf.data.Dataset rejection_resample to limit repeats from same temporal group
- Set max_repeats parameter to limit how many times same group can appear per epoch
- This is simpler but less precise than group-aware sampling

RECOMMENDATION: Use group-aware sampling by (person, temporal_group, class_id) for V5.

4. CORRECTED PERSON-CLASS SAMPLING STRATEGY
===============================================================================

4.1 CORRECTED Weight Calculation and Normalization
ORIGINAL ISSUE: Rounding 91.56 to 92 for all 50 combinations gives 4,600 samples (exceeds 4,578)

CORRECTED ALGORITHM:
1. Calculate base_target = floor(91.56) = 91 samples per combination
2. Calculate remainder = 4,578 - (50 × 91) = 28 samples
3. Distribute remainder by adding 1 sample to 28 randomly selected combinations
4. Final distribution: 22 combinations get 91 samples, 28 combinations get 92 samples
5. Total: 22 × 91 + 28 × 92 = 2,002 + 2,576 = 4,578 ✓

WEIGHT NORMALIZATION for TensorFlow:
- If using tf.data.sample_from_datasets with weights:
  - Calculate raw_weight(p,c) proportional to 1/n(p,c)
  - Normalize all weights to sum to 1.0
  - TensorFlow's weighted sampling will naturally approximate the target distribution
  - The exact per-epoch count may vary slightly due to probabilistic sampling
- If using deterministic sampling (recommended for exact budget):
  - Pre-calculate exact sample counts per combination (91 or 92)
  - Use deterministic sampling without random weighted sampling
  - This guarantees exactly 4,578 samples per epoch

RECOMMENDATION: Use deterministic sampling with pre-calculated counts for exact budget control.

4.2 Exact Number of Samples per Person-Class Combination
- 22 person-class combinations: 91 samples each
- 28 person-class combinations: 92 samples each
- Total: 4,578 samples per epoch
- Selection of which 28 get 92 samples: random or round-robin across epochs

4.3 Expected Repeated Selections
- For underrepresented combinations (e.g., friend 1, class 0 with 50 images):
  - Target per epoch: 91 or 92 samples
  - Available images: 50 images
  - Each image will appear: 91/50 = 1.82 times per epoch (on average)
  - Some images will appear 1 time, some 2 times due to deterministic allocation
- For overrepresented combinations (e.g., "me", class 0 with 214 images):
  - Target per epoch: 91 or 92 samples
  - Available images: 214 images
  - Each image will appear: 91/214 = 0.42 times per epoch (on average)
  - Many images will not appear in a given epoch
- Over multiple epochs, all images will be seen, but underrepresented images more frequently

4.4 How All Ten Classes Remain Represented
- Deterministic allocation ensures each person-class combination gets 91 or 92 samples
- Each of the 10 classes is represented in all 5 persons
- All 50 combinations appear in every epoch
- This GUARANTEES all 10 classes appear in every epoch (deterministic, not probabilistic)

4.5 Implementation of 4,578-Sample Epoch Budget
DETERMINISTIC SAMPLING (Recommended):
1. Pre-calculate: 22 combinations get 91 samples, 28 combinations get 92 samples
2. For each combination, deterministically sample exactly N images
3. If N > available images, sample with replacement
4. If N <= available images, sample without replacement
5. Total per epoch: exactly 4,578 samples

ALTERNATIVE (Weighted Probabilistic):
1. Use tf.data.sample_from_datasets with normalized weights
2. Set sample count to 4,578
3. TensorFlow samples approximately 4,578 according to weights
4. Actual count may vary slightly (±10-20 samples)
5. This is simpler but less precise

RECOMMENDATION: Use deterministic sampling for exact budget control.

4.6 Group-Aware Sampling Implementation
REVISED TWO-LEVEL STRATEGY:
Level 1: Allocate 91 or 92 samples per person-class combination
- Base: 91 samples for all 50 combinations
- Remainder: +1 sample for 28 randomly selected combinations
- Total: 4,578 samples

Level 2: Distribute across temporal groups within each person-class
- For each person-class combination with G groups and target T samples:
  - Distribute T samples proportionally across G groups
  - If group has n images, allocate: round((n / total_images) * T)
  - Adjust to ensure sum = T
  - Sample from each group deterministically

EXPECTED REPEATED SELECTIONS with Group-Aware:
- Reduces temporal redundancy compared to image-level sampling
- Each group is sampled as a unit (or proportionally)
- Near-identical frames from same burst appear less frequently
- Average repeated groups per epoch: ~60 (as shown in audit)

4.7 Summary of Corrected Sampling
- Exact budget: 4,578 samples per epoch (deterministic)
- Distribution: 22 combinations × 91 + 28 combinations × 92 = 4,578
- All 50 person-class combinations appear in every epoch
- All 10 classes appear in every epoch (guaranteed)
- Group-aware sampling reduces temporal redundancy
- Underrepresented images appear ~1.8x per epoch
- Overrepresented images appear ~0.4x per epoch

8.1 Primary Success Criteria

8.2 Moderate Success Criteria
V5 will be considered moderately successful if:
- Validation macro F1 improves by >2% over V4 (54.99% -> >56.09%)
- Friend 3 or Friend 4 shows >10% improvement
- Friend 5 shows >5% improvement
- Safe driving precision improves on Friend 5

8.3 Trade-off Handling
If macro F1 improves but some participants/classes deteriorate substantially:
- Check if deterioration is in already well-performing participants (e.g., "me", friend 2)
- If deterioration is in already poor participants (friend 3, friend 4), reject
- If deterioration is in specific classes (c5, c7), check if other classes improve
- Accept trade-off if:
  * Overall macro F1 improves by >5%
  * Friend 3 and Friend 4 both improve
  * Worst classes (c5, c7) show any improvement
- Reject trade-off if:
  * Friend 3 or Friend 4 deteriorate by >10%
  * Worst classes (c5, c7) remain at 0% recall
  * Safe driving over-prediction worsens

8.4 Unsuccessful Criteria
V5 will be considered unsuccessful if:
- Validation macro F1 does not improve over V4
- Friend 3 and Friend 4 show no improvement or deterioration
- Friend 5 shows no improvement
- Safe driving over-prediction worsens
- Trade-offs are unacceptable per above criteria

If Experiment D (combined approach) succeeds:

===============================================================================
14. RISKS AND LIMITATIONS
===============================================================================

14.1 Dataset Limitations
- Only 6 people total - insufficient for robust generalization
- Friend 5 is the only held-out person - limited evaluation
- Session distribution mismatch is fundamental - may not be fully solvable
- Class imbalance in some classes (especially on Friend 5)
- Temporal groups may not perfectly separate all contexts

14.2 Sampling Risks
- Person-group-class deterministic balanced sampling may reduce overall accuracy on "me"
- May not improve Friend 5 performance if session differences dominate
- Deterministic sampling may require more epochs to converge
- Target distribution (91/92 per combination) may not be optimal
- Group-aware sampling is more complex than image-level sampling
- Deterministic sampling implementation may introduce bugs

14.3 Augmentation Risks
- Excessive augmentation may degrade model performance
- Brightness/contrast augmentation may not fully capture session differences
- Augmentation may remove important visual cues for certain classes
- Visual inspection needed to verify augmentation quality
- May need to tune augmentation parameters

14.4 Generalization Risks
- May not achieve >50% accuracy on Friend 5
- May still fail on Operating radio and Reaching behind
- May still over-predict safe driving on unseen data
- Session distribution mismatch may be fundamental barrier
- Person-specific features may still dominate learned features

14.5 CPU-Only Training
- Slower training than GPU
- Limits ability to run many experiments
- May restrict hyperparameter tuning
- Longer experiment cycle time

14.6 Experiment Control Risks
- Different checkpoint selection (macro F1 vs accuracy) may confound comparison
- Different early stopping patience may affect convergence
- Different learning rates may affect performance
- Need to isolate effects of each change carefully
- Group-aware deterministic sampling complexity may introduce bugs
